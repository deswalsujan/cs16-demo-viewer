# Working on this repo

Who the viewer is for, in Sujan's words (30 Oct 2026): "The viewer is for CS 1.6 players who want to watch HLTV and POV demos in the browser without opening the game, with easier controls and more information than the game's own player, and to find wallbangs; a second use is admins checking suspected cheaters with **See through walls**."

Rules for agents working in this repo, so nothing is lost between chats and machines. Claude Code loads this file, `STATE.md` (what's open, what's decided) and `LIMITS.md` (what the viewer can't do yet) through `CLAUDE.md`; other tools read this file directly.

## Before changing anything
- `STATE.md` and `LIMITS.md` are already loaded (Claude Code imports them; with another tool, read them first). Then read the last two release entries of CHANGELOG.md, then only the IDEAS.md item you are about to touch. IDEAS.md starts with the checklist of everything open, each item as a short header; IDEAS-ARCHIVE.md holds, word for word and under the same block names, the full text of every item IDEAS.md had on 29 Oct 2026, so search it when a header isn't enough; some headers were shortened, renamed or added since, so search a distinctive word from the header, not the whole header; CHANGELOG.md says what was built, how it was tested, and what was "Discussed, not changed".
- Don't read CHANGELOG.md, IDEAS-ARCHIVE.md or `docs/review-answers.md` end to end, or all of IDEAS.md: they are long, and `STATE.md` says which part matters. In `docs/review-answers.md`, search for the page's section.
- Discuss issues with Sujan before changing code when he asks for that, and before building any visible change, ask whether he wants to see a mockup first; make one only when he says yes (see `docs/` for the approved ones). Rule set 2 Oct 2026, replacing "always make a side-by-side image".
- Batch related features into one mockup round, one build and one test run (Sujan, 3 Nov 2026): one mockup for features that touch the same part of the viewer, then one branch, one pull request and one run of the release checks for them (seven until 0.26.27, eight since 0.26.28).
- Things found while building go to IDEAS.md for later, unless the current change caused them (Sujan, 3 Nov 2026). A problem the change itself brings is fixed in the same pull request; anything older, or next to it, is written down with where it was seen, and the work goes on.
- Before any run that takes more than a few minutes (a full test run, a big measurement), say how long it will take and wait for Sujan's go (Sujan, 2 Nov 2026; it replaced "warn before anything that runs a long time").
- Think about the user experience in every change (Sujan, 25 Oct 2026): what a first-time user sees, whether a feature or option needs a tooltip, and whether the UI could be simpler. Open UX items are under "User experience" in IDEAS.md.
- Every user gets the same experience on Mac and Windows, in Chrome and Edge, on any screen size. A bug that hits one platform only counts as a real bug (Sujan, 2 Nov 2026). Phones aren't a target: the viewer needs a Half-Life folder, which no phone has, so no phone-width screenshots and no phone width in the checks (Sujan, 3 Nov 2026).
- Never script the Mac's interface: no System Events, keystrokes or clicks in the Mac's own windows and dialogs. A check that needs a click in a system dialog is Sujan's to do (Sujan, 2 Nov 2026).

## How each change ships
Before starting any branch, run `git fetch` and branch from `origin/main`; if a branch has to stack on an open pull request, say which one in the handover (Sujan, 1 Nov 2026).

1. Change `src/`, then `python3 build.py` (writes `index.html` and `dist/artifact.html`).
2. Bump `VERSION` for anything user-facing; add a CHANGELOG entry (Fixed / Changed / Added, "How it was tested", "Discussed, not changed") and its line in the index at the top of CHANGELOG.md (version, date, five words), and update `LIMITS.md` (the known limits). From 0.26.0 on, "How it was tested" is at most five lines: the scripts that passed, on which demos, and a pointer to `tests/logs/<version>.md`, which holds the full log, the measurements that used to go in the CHANGELOG; entries before 0.26.0 stay as they are (agent brief, 30 Oct 2026).
3. Move built items out of IDEAS.md into IDEAS-ARCHIVE.md, word for word, at the top of their block, and add new loose ends to its checklist.
4. Test in the headless browser on Sujan's real files (`tests/README.md`; the demos are listed in `tests/DEMOS.md`), and run the eight checks: `folder_row_test.py`, `start_screen_check.py`, `prefs_check.py`, `demo_search_check.py`, `late_kill_timing_check.py` (guards the 0.15.5 late-kill timing, added 3 Oct 2026) and `panel_click_check.py` (marked "Run on every release" in `tests/README.md`) and `ground_truth_check.py` (Sujan's confirmed wallbangs, scores and K-D, from `tests/expected/`; added 30 Oct 2026): on every expected file, every release, about 1.3 minutes; and `pov_reopen_check.py` (a POV demo playing, then an HLTV demo, then the POV demo again: no error and the 3D view drawing on; added 10 Nov 2026, Sujan: an eighth check since it runs in under a minute, about 16 s; POV demo, HLTV demo, POV demo since the POV mode setting went, 11 Nov 2026); on the Mac with `HALF_LIFE_DIR` set to `~/code/cs16-data/Half-Life` and `DEMO_DIRS` to `~/code/cs16-data/test-demos` (one setting for the demo folders in every test, `tests/README.md`; both exported in Sujan's `~/.zshrc`, which Claude Code's shell on the Mac reads too). The first three need no game files; the last five need `HALF_LIFE_DIR` with Sujan's demos, so they can't run in `check.yml`.
5. Commit, push a branch and open a pull request. GitHub runs `.github/workflows/check.yml` on it (`index.html` must match a fresh build, `tests/notes_check.py` must pass (paths in the notes exist, CHANGELOG.md's newest version is `VERSION`, every `src/` file has a line in "Where the code is" below), and the three checks with no game files must pass); fix a red check before handing it over. Sujan merges it on GitHub (GitHub Pages deploys from main).
- Chain commands so a failing check stops what comes after it: a check before a commit or a push is joined to them with `&&` and its own exit code, never piped through `tail` or `grep` first, whose exit code hides the check's (Sujan, 3 Nov 2026, after a notes check failed and the commit and push went on).
- By-eye round (Sujan, 3 Nov 2026): Sujan's checks by eye of merged builds wait for one sitting that he runs when he chooses. A change adds its checks to IDEAS.md, **By-eye round**, in its own pull request, one line each: what to open, what to look for, the version, the machine; the handover doesn't ask him to check after the merge. A line he passes moves to IDEAS-ARCHIVE.md with the date; one he fails becomes an item in the checklist. Mockups and decisions still go to him when they're ready, and the hold-out answers stay their own item.
- Screenshots for a pull request go on their own branch, `screenshots/<version>`, which is never merged and never deleted, since the pull requests show their pictures from it (Sujan, 3 Nov 2026); they stay out of main, so the repo and GitHub Pages don't carry them.
- Commit messages are "area: imperative subject", with notes in the body; never rewrite history to fix an old message (Sujan, 29 Oct 2026).
- Attribution (Sujan, 29 Oct 2026): Commit messages end with only the line Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com> (or the current model's name), so Claude shows as a contributor. No Claude-Session line and no claude.ai/code link in commits. Pull request descriptions have no 'Generated with Claude Code' line and no session link. Notes, CHANGELOG entries and other repo files never mention Claude Code sessions or link to them. This overrides Claude Code's default attribution lines.
  - The setting lives in `.claude/settings.json` (`attribution.pr` empty, so no pull request line; `attribution.sessionUrl` false, so no session link; `attribution.commit` left unset, so the `Co-Authored-By` line stays).

## Recording what Sujan confirms
- No pull request for notes alone (Sujan, 3 Nov 2026). When Sujan confirms or decides something, it's written down in that turn on the branch being worked on; if there's none, on a notes branch (`notes/<what>`, from `origin/main`), which is pushed and folded into the next code pull request (merged into its branch, or its commits picked onto it). The handover names a notes branch still waiting.
- When Sujan says something is checked, done or decided, in that same turn and on the current branch (the rule above): change its line in `STATE.md` (a replaced decision moves to Superseded, with the date and what replaced it), tick or change the IDEAS.md item, and push it, even when he says "just answer" or "don't act": writing down his answer is not acting on it. Unrecorded confirmations come back as open items in the next session (3 Oct 2026: the 0.13.0 in-game wallbang check and the scope comparison were asked about twice).
- When a claude.ai review page returns answers, copy the answers into the repo in the same turn (the IDEAS.md item, and `STATE.md` for a decision); the page URL stays only as a link to the pictures. The answers of every page up to 28 Oct 2026 are in `docs/review-answers.md`, copied from the pages' stores on 29 Oct 2026. A new page's answers go into that file as a new section, newest last, in the same turn they come back (Sujan, 29 Oct 2026).
- When a confirmation could match more than one open item (two lists of "removed wallbangs"), ask which one before ticking, and quote the item's name back.
- In messages listing open items, say what each check is in one line (what to open, what to look for), not only its release number.

## Facts
- Verify factual claims before stating them, and say plainly when unsure.
- **Guns:** before saying what a gun can or can't do (wallbangs, penetration, damage), read that weapon's own code in ReGameDLL (`regamedll/dlls/wpn_shared/wpn_<gun>.cpp`, and `FireBullets3` / `FireBullets` in `cbase.cpp`), never a general number. ReGameDLL is a reverse-engineered copy of CS 1.6's game code. Sujan's in-game checks outrank code readings. (Rule set 1 Oct 2026 after a wrong claim that the USP could wallbang thin cover; it can't.)
- Never bundle or host Valve's files. Everything game-related (maps, overviews, models, sounds, kill feed icons) is read from the player's own Half-Life folder.
- The viewer collects no user data (Sujan's rule, 2 Nov 2026). Since 0.26.9 nothing on the page loads from another site: the fonts are Tahoma and Verdana from the player's own computer (Google Fonts, used until then, sent each visitor's IP address to Google), and `tests/start_screen_check.py` fails on any request to another site.

## Where the code is
`build.py` makes `index.html` from these: `src/template.html` is the page, each `src/ui/` file and `app.css` go in at its own `/*INLINE name*/` line in page order (`src/ui/size.js` in the page's head, the rest in the page's script), the reader runs in a Web Worker, and `stock.js`, `mdl.js`, `players3d.js`, `audio.js` and `shotfx.js` go into the 3D view's script. One line per file, from its header comment; code locations in notes from before the split of 29 Oct 2026 point at the old one-file `src/template.html`.

- `src/template.html`: the page itself: header, view, side panel, bottom bar, cards and panels, with an `/*INLINE name*/` line for each file below.
- `src/app.css`: the page's styles, every size written `calc(Npx * var(--ui))` for **Interface size** (0.26.13).
- `src/ui/size.js`: **Interface size**: the scale (`UI`, `--ui`) from the window and the setting (`applyUiSize`), run in the page's head; Auto follows a resize or a move to another screen.
- `src/demo.js`: the .dem reader (`parseDemo`): players, sampled positions, kills, rounds, bomb events, shots, sounds, health; latency (svc_pings); in POV demos also his view, HUD, the hits on him, the plant and defuse bar, his Tab presses, flashbangs (ScreenFade), his radar (Radar, BombDrop, BombPickup) and who has the bomb (ScoreAttrib); message layouts from hlviewer.js.
- `src/bsp.js`: the .bsp and .wad reader: what's solid to sight and to bullets (`solidModels`, `solidAlong`), the texture a bullet enters at each surface (`hitTextures`), doors and other movers (`brushPose`), the mesh the 3D view draws (`buildMesh`).
- `src/mdl.js`: studio model (.mdl v10) reader and posing (`parseMdl`, `mdlPose`).
- `src/players3d.js`: player models in 3D: loading (`modelEntry`), gait and aim (`posePlayer`), deaths and corpses, the gun in **Player's eyes**.
- `src/audio.js`: sound: .wav decoding, gunshots, footsteps and radio lines placed around the listener (`soundTick`).
- `src/shotfx.js`: shot feedback in 3D: the gun flash on every player and in **Player's eyes** (`fxThirdPerson`, `fxViewFlash`), shells in **Player's eyes** and **POV mode** with their landing sound (`fxShells`, `fxShellSounds`), blood puffs where the server marked a hit (`fxBlood`).
- `src/stock.js`: fingerprints of the stock CS 1.6 models, to spot custom ones.
- `src/vendor/three.min.js`: three.js r128 (MIT), the file cdnjs serves, built into the page; the tests serve it to older builds.
- `src/view3d.part.js`: the 3D view (three.js): cameras, each frame (`update3`), hit numbers by **Damage numbers** (`numberGroups`) with the red skull, kill rings, the sniper scope (`SCOPE_STYLE`); the wallbang picture check (`checkSeen`); **POV mode**: his view, crosshair, HUD as the game draws it (`drawPovHud`), the hit arcs (`povPainAt`), the plant and defuse bar (`drawPovBar`), his radar (`drawPovRadar`) on the added HUD layer (`#hud3`), flashbangs (`povFlashAt`, `povFlash`), spectator bars, the hidden-enemies note and its ! on **See through walls**.
- `src/ui/common.js`: shared state (`D` the demo, `M` the match, `T` the time), colours, saved settings, small helpers (`weaponShort`).
- `src/ui/folder.js`: the Half-Life folder, chosen with the browser's ordinary folder pick on every visit (`pickFolder`, `hlPicked`, `hlRender`; 0.26.11), the demo list and its check for demos deleted since the pick (`checkDemoList`), centre-screen messages, kill feed icons.
- `src/ui/open.js`: opening a demo in the Web Worker (`loadDemoFile`), and joining a map recorded in parts (`joinDemos`, `openJoined`).
- `src/ui/join.js`: finding a map's other parts and their order (`findOtherParts`, `suggestOrder`, `orderProblem`), what joining them in an order would count (`carryFacts`), and the Join card.
- `src/ui/map.js`: the overview image and the map geometry (`loadMap`).
- `src/ui/wallbangs.js`: the wallbang finder (`computeWallbangs`, `tooMuchDamage`, each wall's material `wallKeeps`), wallbang damage and loose wallbangs from damage (`computeHits`, which also keeps every hit pinned on a shooter), kill details' bullets, body parts and earlier damage (`killHits`, `bodyPart`, `earlierDamage`), and the stretches the server announced as live (`liveWindows`).
- `src/ui/match.js`: kills moved back to the real moment (`retimeKills`) and the match structure (`derive`): people across connections, rounds, live rounds (a half replayed from 0:0, a half carried on into a later file), score, teams (`groupTeams`).
- `src/ui/skips.js`: skips in the recording (`findSkips`), and the STRICT WB, LOOSE WB and UNSURE tags with their tooltips.
- `src/ui/names.js`: short names without the clan tag or sponsor (`shortNames`), and the skull (`SKULL`, `SKULL_D`).
- `src/ui/grenades.js`: smokes, HE and flash bursts the demo has no object for (`addNadesFromEvents`).
- `src/ui/lookups.js`: what's true at a moment: sniper zoom (`zoomLevel`), health (`hpAt`), kit and bomb (`packAt`), latency (`pingAt`), HLTV slow motion (`slowAt`), the round and C4 timers (`clockAt`, `c4Countdown`), team names, player stats (`statsFor`), broken breakables and doors (`brokenAt`, `posesAt`), the round at a time (`roundAt`).
- `src/ui/after-load.js`: what runs once a demo is open (`onDemo`), **POV mode**'s data (`povApply`), what each kind of demo offers (`demoOffers`, `applyOffers`), closing a demo.
- `src/ui/sidebar.js`: the side panel's Rounds, Kills, Players and Wallbangs tabs (`renderPane`, `killHtml`), kill details under the picked kill (`killDetailsHtml`).
- `src/ui/playback.js`: play, seek, speed and rounds, the Tab scoreboard in the game's look (`showScoreboard`; his own Tab in **POV mode**, `povTabTick`), the HUD (`updateHud`).
- `src/ui/radar.js`: the 2D radar (`draw`), fitting the map above its controls (`fitView`), where a player is between snapshots (`playerState`), picking players, the heatmap.
- `src/ui/timeline.js`: the timeline under the view (`drawTimeline`).
- `src/ui/loop.js`: the frame loop (`frame`), each part of a frame in its own try/catch (`framePart`), full screen, and **View settings**: its saved settings and **Vanilla** (`setVanilla`).
- `src/ui/theatre.js`: Theatre mode, and the saved view settings (`savePrefs`).
- `src/ui/summary.js`: the load summary (what loaded, what's custom or missing), the card for a demo that can't play, **Count them** (`setCount30`).
- `src/ui/debug.js`: **Copy debug info** for bug reports (`debugInfo`), and errors caught in the frame loop, each recorded once (`frameError`).
- `src/ui/clear.js`: **Clear saved files**.
