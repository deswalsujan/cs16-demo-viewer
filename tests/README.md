# Tests and measurements

Scripts used while building 0.8.0 (1 Oct 2026) to 0.25.0 (29 Oct 2026). They're the starting point for the test suite in [IDEAS.md](../IDEAS.md). They're run by hand, except three that need no Half-Life folder (`start_screen_check.py`, `prefs_check.py`, `folder_row_test.py`): since 29 Oct 2026 those run on GitHub on every pull request and every push to main, after a check that `index.html` matches a fresh build of `src/` (`.github/workflows/check.yml`).

Each release's full test log, from 0.26.0 on, is in `logs/<version>.md`; its CHANGELOG entry keeps a few lines and a pointer (30 Oct 2026).

## Setup

1. Python 3 with Playwright, at the pinned versions: `pip install -r tests/requirements.txt`, then `python3 -m playwright install chromium` (`check.yml` installs the same file). On Sujan's Mac they're in `~/.venvs/cs16-tests`: put its `bin` first on `PATH`, or every browser check fails in a second (`compare_all.sh` then still says all demos are identical; look for its "NO RESULT" lines).
2. three.js r128 is in the repo, `src/vendor/three.min.js`, and built into the page since 0.26.2. Builds before that load it from cdnjs; the scripts serve them the same file in place of the CDN, so they also run without internet.
3. Node 18 or later, for the demo data probes.
4. Build the viewer first (`python3 build.py`). The browser checks run against `index.html` in the repo root unless told otherwise.

## Browser checks (headless Chromium)

`harness.py` loads a built page, feeds it the Half-Life folder (with the `DEMO_DIRS` demos added), opens a demo, waits for the 3D map, then runs one or more page scripts in order and prints what each returns. It copies the page and adds a small hook (`window.__v`) so scripts can reach the viewer's internals; the shipped page is never changed.

```
cd tests
export HALF_LIFE_DIR=~/code/cs16-data/Half-Life DEMO_DIRS=~/code/cs16-data/test-demos
python3 harness.py ../index.html page/smoothness_and_frame_cost.js
python3 harness.py ../index.html page/see_through_walls.js,page/team_colours.js,page/figure_fallback.js shot
```
A third argument saves a screenshot after each script (`shot0.png`, `shot1.png`, ...). Loading the Dust2 demo with its map takes 1 to 3 minutes.

## Wallbang ground truth

`tests/expected/` holds one file per demo, named by the demo's file name without `.dem`, with what Sujan has confirmed, so a change to the viewer that stops agreeing with him fails `ground_truth_check.py` (an outside audit's first item, 30 Oct 2026). Each file has the demo's `sha256`, `match` (teams, map, event, as notes name it), `event` (as `tests/DEMOS.md` has it), `map`, and where Sujan confirmed them: `score` (`value`, `live` rounds, `any_order` when the source names only the winner), `kd` (`player`, `kd`), `count_them` (the same with Count them on) and `joined` (a joined map's `parts` and their `sha256`, in its first part's file); then `kills`, each with `round`, `timer`, `killer`, `victim`, `gun`, `expected` and, for a known disagreement, `known_gap`. Every score, K-D and kill has a `source`: the STATE.md decision, `docs/review-answers.md` section, IDEAS-ARCHIVE.md item or CHANGELOG entry it comes from, with the date.

How they were filled (Sujan, 30 Oct 2026; STATE.md Decisions):
- Only from what Sujan confirmed: `docs/review-answers.md`, the confirmed lines in IDEAS-ARCHIVE.md, STATE.md Decisions, the K-D and score tables in CHANGELOG 0.14.2, 0.15.0 and 0.15.1, and the 0.15.5 removals. Never a kill because the finder lists it.
- `expected` is `strict`, `loose` (part of the victim in view, from the picture check), `loose-damage` (loose from the demo's damage), `none`, or `wallbang` where Sujan said it's a wallbang but not which kind (strict or either loose passes).
- A kill is found by round, killer and victim (a player dies once a round), with names exactly as the viewer gives them, looked up in the demo's kill list; `timer` and `gun` are compared only where a source gives them, and left empty (null) otherwise.
- "Part of him was in view" answers from before the strict and LOOSE split (23 and 24 Oct 2026) are `loose`, by the 25 Oct rule. A later answer wins over an earlier one; both are cited.
- The test leans toward the current finder: Sujan's answers were mostly given on its own pictures, so a change to how the finder judges can fail answers that were never checked against another picture (Sujan, 1 Nov 2026, deciding to keep judging at the shot).
- `known_gap`: Sujan's eye and the viewer disagree, and the disagreement is accepted: in `LIMITS.md`, by his 5 Oct 2026 decision to leave the hidden check as in 0.17.0, or because a rule of the finder's own (not one of his decisions) dropped the kill, or until a fix ships (Sujan, 30 Oct 2026). ## Lessons

- The headless browser draws 3D without a graphics chip, so it's slow. Checks that wait a fixed time can fail there and pass on a real machine: wait for the outcome instead, and confirm timing failures by hand before chasing them. The one Theatre check that failed on the 14-inch setup worked on a real MacBook.
- Give an estimate before long runs. One full Theatre round across five setups takes about 45 minutes.
- Parallel runs of `harness.py` need a copy of the page each: it writes `_test_<page name>` beside the page and deletes it at the end, so two runs on one page name break each other (`compare_all.sh` does this). Found 2 Oct 2026.
- The browser doesn't read symlinked folders inside the folder given to it: a test folder built with `ln -s` to the maps gave every demo an empty wallbang list, identical on both builds, so the comparison passed with nothing compared. Use real copies or hard links (`cp -al`); `wallbang_list.js` now says "not loaded" when the map is missing. Found 23 Oct 2026.
- A page script that opens another demo and waits for it must wait for a new demo object (`D !== old`), not just for `D.parts` or `M`: those still hold the previous demo's values until its counting has run, so the check passes early and reads old numbers. Found 2 Oct 2026, twice.
